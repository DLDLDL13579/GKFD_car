> 建立：2026-09-09。本文只补充**多机协同相关**的运维要点；主车完整项目文档见《小微项目说明.md》。

## 1. 角色定位

主车 = **多机协同调度中枢 + 人机接口**：
- 域 1 上运行全栈：底盘(wheeltec_robot)、激光(lslidar)、EKF(odom_combined)、相机(realsense)、语音(aiui/wheeltec_mic)、大模型(largemodel)、rosbridge/webrtc、system_manager(MQTT 桥)
- 通过 domain_bridge / 自研中继 与 robot1(域21)、狗(域11) 互联
- system_manager 原生订阅 robot_1/robot_2 全部状态并经 MQTT(127.0.0.1:1883) 上发远端

## 3. 下行中继原理（为何不用 domain_bridge）

- **domain_bridge 0.5.0 无法向"非默认域"发布**：主车域1 → robot1 域21 方向端点存在但零数据（实测 40 条发布零到达）；反向（21→1）正常。
- 因此下行走两个进程：`src`（域1，订阅主车调度话题）→ 本机 TCP(127.0.0.1:39211/39212) → `dst`（域21/域11，发布到次车域）。
- 消息协议：`4B 长度 + "topic|type|" + CDR 序列化字节`；断线自动重连。
- 修复记录：dst 的 `create_connection(timeout=2)` 使 recv 带超时，空闲被误判断线重连（会漏消息）——连接成功后必须 `settimeout(None)`。

## 4. system_manager 的多机接口（已在代码中，无需改）

- 下行发布：`/robot_1/{cmd_vel, goal_pose, initialpose}`、`/robot_2/{...}`、`/robot_1/navigate_to_pose/_action/cancel_goal`
- 上行订阅：`/robot_1/{odom, soldier_pose, battery_state, scan}`、`/robot_2/{odom, soldier_pose, battery_state}`、主车自身 `/odom /odom_combined /map /PowerVoltage /robot_charging_flag /feedback_words`
- MQTT：连接本地 broker 127.0.0.1:1883（ESTABLISHED 已验证），`_mqtt_pub` 统一上发
