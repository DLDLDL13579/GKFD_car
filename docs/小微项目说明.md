## 1. 项目概述

本项目是一个基于 **ROS2 Humble + 阿里通义千问(Qwen)大模型** 的语音交互机器人控制系统，搭载在 **WheelTec 全向麦克纳姆轮底盘** 上。用户通过**自然语音**向机器人下达指令，大模型理解语义后拆解为机器人动作序列，再由执行层完成实际控制。

### 1.1 核心能力

| 能力域 | 说明 |
|--------|------|
| 🎤 **语音指令理解** | 支持中文语音输入，大模型解析意图并规划动作 |
| 🗺️ **SLAM 建图** | 基于 RTAB-Map 的视觉-激光融合建图。←订正2026-09-20：产物 `my_map.*` 会覆盖在用地图，若在用图为跨车融合图，建图后需把新库坐标系变换回融合图坐标系 |
| 🧭 **自主导航** | 基于 Nav2 + **RTAB-Map 重定位**（2026-09-20 起为默认主线；AMCL 定位保留可切换）的路径规划与导航 ←订正2026-09-20 |
| 👁️ **视觉识别** | 调用 Qwen3-VL 多模态模型拍照识别环境、物体检测 |
| 👣 **视觉/巡线跟随** | KCF 跟踪、颜色巡线等跟随功能 |
| 🔌 **自动充电** | 视觉(AprilTag)伺服对接充电桩，全程自动化 |
| 🌐 **MQTT 远程桥** | 支持 WebRTC 推流 + MQTT 云端通信 + Web 控制台 |
| 📍 **位置记忆** | 语音标记并记忆地图关键点位 |

### 1.2 技术栈

| 层 | 技术 |
|----|------|
| 硬件 | NVIDIA Jetson, 麦克纳姆轮底盘, 深度相机(RGB-D), 激光雷达, IMU, 麦克风阵列 |
| 中间件 | ROS2 Humble, Nav2, RTAB-Map, cv_bridge, tf2 |
| AI 模型 | 阿里百炼-通义千问 (`qwen3-vl-plus` 多模态模型) |
| 语音 | 讯飞 AIUI 语音识别 (wheeltec_mic_aiui) |
| 通信 | MQTT Bridge (system_manager + WebRTC + Web Console) |

### 架构要点

1. **决策-执行分离**：`model_service` 只做语义理解和动作规划，`action_service` 只做动作执行
2. **异步通信**：通过 ROS2 Action（`Progress.action`）传递动作列表，天然支持打断和反馈
3. **多模态输入**：支持纯文本指令（语音转文字后）和视觉指令（拍照理解场景）
4. **上下文记忆**：大模型维护对话历史，同一任务周期内保持上下文连贯

## 4. 核心模块详解

### 4.1 model_service.py（决策层）

**节点名**：`LargeModelService`

**职责**：接收语音识别文本/视觉触发，调用大模型进行语义理解和动作规划，将动作列表通过 Action Client 发送给执行层。

**关键流程**：

```
语音输入(/voice_words) → asr_callback()
    → action_agent(type="text", prompt)
        → 新任务周期: 重置 LLM 上下文(init_Multimodel_history)
        → 双模型模式: TaskDecision() 预处理
        → instruction_process()
            → multimodelinfer(prompt) 调用大模型
            → extract_json_content() 提取 JSON
            → send_action_service(action_list) 发送动作
```

**关键方法**：

| 方法 | 功能 |
|------|------|
| `init_param_config()` | 读取 `param.yaml` 参数（text_chat_mode, is_dual_model） |
| `init_largemodel()` | 初始化大模型接口 + 地图映射 |
| `init_ros_comunication()` | 创建订阅者/发布者/Action Client |
| `asr_callback(msg)` | 语音转文字回调入口 |
| `seewhat_callback(msg)` | 视觉触发入口（拍照后意图分析） |
| `action_agent(type, prompt)` | 任务调度：上下文管理 + 推理 |
| `instruction_process(type, prompt)` | 实际推理，支持 text/image 两类 |
| `send_action_service(actions, text)` | 将动作列表发送给 ActionServer |
| `extract_json_content(raw_content)` | 从大模型返回中提取 JSON |
| `get_map_mapping()` | 从 `map_mapping.yaml` 读取地图映射 |

**订阅话题**：
- `/voice_words` (String) — 语音识别结果
- `/actionstatus` (String) — 动作执行反馈状态
- `/seewhat_handle` (String) — 视觉触发信号

**发布话题**：
- `/feedback_words` (String) — 机器人语音回复（给 TTS）

### 4.2 action_service.py（执行层，核心）

**节点名**：`action_service_node`

**职责**：接收大模型规划的动作列表，逐一执行具体的机器人控制函数。是整个系统中代码量最大、逻辑最复杂的模块（约1200行）。

**关键流程**：

```
动作列表 → execute_callback()
    → 逐个解析: re.match(r"(\w+)\((.*)\)", action)
    → 动态调用: getattr(self, action_name)(*args)
    → 每个动作执行完后发布 feedback
    → 全部完成后发布 finishtask → model_service 开启新任务周期
```

**动作执行函数一览**：

#### 基础运动类

| 函数 | 参数 | 说明 |
|------|------|------|
| `set_cmdvel(linear_x, linear_y, angular_z, duration)` | 线速度 x/y, 角速度 z, 持续时间 | 通用速度控制，带障碍物检测 |
| `move_left(angle, angular_speed)` | 角度(度), 角速度(rad/s) | 左转指定角度 |
| `move_right(angle, angular_speed)` | 角度(度), 角速度(rad/s) | 右转指定角度 |
| `wait(duration)` | 等待秒数 | 暂停等待 |
| `stop()` | 无 | 立即停车 |

#### 导航类

| 函数 | 参数 | 说明 |
|------|------|------|
| `navigation(point_name)` | 字母点位标识（如 "A"） | 导航到指定目标点 |
| `navigation_start()` | 无 | 启动导航系统（守护线程） |
| `navigation_stop()` | 无 | 停止导航系统 |
| `load_target_points()` | 无 | 从 YAML 加载地图点位到 `navpose_dict` |

#### 建图类

| 函数 | 参数 | 说明 |
|------|------|------|
| `slam_start()` | 无 | 启动建图（守护线程 + 回环检测监控） |
| `slam_stop()` | 无 | 保存地图 + 停止建图 |

#### 视觉/跟随类

| 函数 | 参数 | 说明 |
|------|------|------|
| `seewhat(func)` | 可选功能名 | 拍照保存 → 触发大模型视觉分析 |
| `KCF_follow(x1, y1, x2, y2)` | 像素坐标(1000比例) | KCF 目标跟踪跟随 |
| `visual_follower(color)` | 颜色名 | 视觉跟随指定颜色物体 |
| `line_follower(color)` | 颜色名 | 巡线跟随 |
| `laser_follower()` | 无 | ⚠️ 已物理屏蔽（安全原因） |

#### 充电类

| 函数 | 参数 | 说明 |
|------|------|------|
| `auto_charge()` | 无 | 全自动充电：导航→视觉对齐→盲推入库 |
| `leave_charge()` | 无 | 陀螺仪闭环直行脱离充电桩 |
| `visual_align()` | 无 | 三阶段视觉伺服（AprilTag）精确对齐 |

#### 系统类

| 函数 | 参数 | 说明 |
|------|------|------|
| `shutdown()` | 无 | 关机（sudo poweroff） |
| `restart()` | 无 | 重启（sudo reboot） |
| `get_current_pose(name)` | 中文名称 | 记录当前位置到地图文件 |
| `set_initial_pose_to_origin()` | 无 | 重置位置到**标准发车点**（重定位）。←订正2026-09-20：该方法原先固定发布原点 `(0,0,0)`，已改为发布类常量 `START_POSE_X/Y/YAW_DEG`（实测发车点），与 `~/maincar_start_pose.txt` 保持一致 |
| `stop_follow()` | 无 | 停止所有跟随进程 |
| `finishtask()` | 无 | 结束当前任务周期 |

**订阅话题**：
- `/camera/color/image_raw` (Image) — 相机图像
- `/awake_flag` (Int8) — 打断信号（1=打断）
- `/object_tracker/current_position` (Position) — 激光雷达障碍物位置
- `/kcf_cmd_vel` (Twist) — KCF 跟随速度命令（安全过滤）

**类**：`model_interface`

## 9. 大模型决策-执行流程

### 9.1 完整交互流程

```
用户说："去饮水机倒杯水"
    │
    ▼
[wheeltec_mic_aiui] ASR 识别
    │  /voice_words = "去饮水机倒杯水"
    ▼
[model_service] asr_callback()
    │
    ├─ new_order_cycle? → 是 → 重置 LLM 上下文
    │   init_Multimodel_history(get_prompt())
    │   (注入: 角色设定 + 动作库 + 地图映射 + Few-Shot)
    │
    ├─ is_dual_model? → 是 → TaskDecision("去饮水机倒杯水")
    │   (百炼 App 做任务类型分类/意图确认)
    │
    ├─ instruction_process(type="text", "去饮水机倒杯水")
    │   │
    │   ├─ multimodelinfer("去饮水机倒杯水")
    │   │   │ 使用 OpenAI 兼容接口，response_format="json_object"
    │   │   ▼
    │   │   LLM 返回:
    │   │   {
    │   │     "response": "好嘞，马上去饮水机！",
    │   │     "action": ["navigation(C)", "finishtask()"]
    │   │   }
    │   │
    │   ├─ extract_json_content() 提取 JSON
    │   ├─ json.loads() 解析
    │   └─ send_action_service(["navigation(C)"], "好嘞，马上去饮水机！")
    │
    ▼
[action_service] execute_callback()
    │
    ├─ 遍历 actions:
    │   ├─ "navigation(C)" → self.navigation("C")
    │   │   ├─ navpose_dict["C"] → 目标位姿
    │   │   ├─ navclient.send_goal_async(目标)
    │   │   ├─ 等待导航完成 (while 循环)
    │   │   └─ 发布 action_status_pub("navigation_2")
    │   │
    │   └─ "finishtask()" → self.finishtask()
    │       └─ action_status_pub("finish")
    │
    └─ goal_handle.succeed()
    │
    ▼
[model_service] actionstatus_callback()
    │  msg.data == "finish" → new_order_cycle = True
    │  (下一轮对话开启新的上下文)
    ▼
用户收到 TTS 语音："好嘞，马上去饮水机！"
```

## 11. 常见问题与解决

### 11.1 启动失败

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| `ModuleNotFoundError: No module named 'dashscope'` | 缺少 Python 依赖 | `pip install -U dashscope openai` |
| `ModelInitError: 大模型密钥无效` | API Key 错误或过期 | 检查 `model_config.yaml` 中的 `tongyi_api_key` |
| `大模型连接失败` | 网络不通 | `ping dashscope.aliyuncs.com`，检查 DNS/防火墙 |
| 启动后无反应 | 系统服务冲突 | `sudo systemctl stop largemodel-control` 后再手动启动 |

### 11.2 语音识别问题

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| 说话无反应 | 麦克风未加载 | 检查 `/dev/wheeltec_mic` 是否存在 |
| 识别不准确 | 环境噪音大 | 靠近麦克风说话，降低环境噪音 |
| `wheeltec_mic` 启动失败 | 串口占用 | `sudo lsof /dev/wheeltec_mic` 检查占用进程 |

### 11.3 大模型推理问题

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| `The format was unexpected` | LLM 返回非 JSON 格式 | 检查 Prompt 是否正确，模型版本兼容性 |
| 返回的动作列表为空 | LLM 不理解指令 | 用更明确的指令，或查看原始返回日志 |
| 动作函数不存在 | LLM 编造了不存在的函数 | Prompt 中的 Few-Shot 不足，需补充 |
| 执行超时 | 网络或 API 限流 | 检查 API 配额，考虑降级模型 |

### 11.4 导航问题

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| 导航目标被拒绝 | 地图中无此点位或点位无效 | 检查 `map_mapping.yaml`，确保点位在可达区域 |
| 导航中迷路 | 重定位失败 | 说「把你放到原点了」触发 `set_initial_pose_to_origin()`（重置到标准发车点）←订正2026-09-20 |
| 导航目标能收但车不动、`bt_navigator` 一直 inactive | 定位初值偏离实际位置过远，`map→odom` 不发布，costmap 等 TF 超时 | 用 `~/lgm.py` 重测当前位姿并写入初始位姿；判据是日志出现 `Managed nodes are active` ←新增2026-09-20 |
| `起点在障碍物内` | 充电后导航起点在膨胀区 | 先执行 `leave_charge()` 再导航 |
| 导航不启动 | Nav2 节点未运行 | `ros2 launch largemodel largemodel_nav.launch.py` |

### 11.5 充电对接问题

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| 找不到充电桩二维码 | AprilTag 未检测到 | 清洁二维码，确保光照充足 |
| 视觉对齐超时(60秒) | 机器人位置偏差太大 | 检查充电桩预对接点是否准确 |
| 盲推后未接触 | 盲推时间/距离不够 | 调整 `BLIND_PUSH_TIME` 参数 |
| `charge_key is None` | 地图中无"充电桩"记录 | 在 `map_mapping.yaml` 中确保有 `name: 充电桩` 的点位 |
| AprilTag 节点未启动 | TF 链路缺失 | 检查 camera_link 到 optical frame 的静态 TF |

### 11.6 建图问题

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| 地图保存失败 | 磁盘空间不足或权限问题 | `df -h` 检查空间；确认目录有写权限 |
| rtabmap.db 未找到 | 数据未同步 | 检查 `~/.ros/rtabmap.db` 是否存在 |
| 建图质量差 | 参数不合适 | 调整 `Grid/CellSize`、`Grid/RangeMax` 等参数 |

### 11.7 传感器异常

系统每5秒自动监测三种核心传感器：
- 📷 **相机** (`/camera/color/image_raw`)
- 📡 **雷达** (`/scan`)
- 🧭 **里程计** (`/odom`)

传感器异常时会自动 TTS 播报 "数据异常，请检查: 雷达"。

### 11.8 其他问题

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| 机器人不响应新指令 | 上一个任务未结束 | 等待 `actionstatus = "finish"` 或重启服务 |
| 打断不生效 | `awake_flag` 话题未发布 | 确认 `ros2 topic pub /awake_flag std_msgs/Int8 "{data: 1}"` |
| Web 控制台连不上 | MQTT 桥未启动 | 检查 `mqtt_bridge_ros2` 节点状态 |
| DISPLAY 错误 | KCF 需要 X 环境 | 确保 `QT_QPA_PLATFORM=offscreen` 已设置 |

```
导航失败？

└─ 检查是否在障碍物区 → 执行 leave_charge()
```
